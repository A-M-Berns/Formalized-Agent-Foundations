Formalized Agent Foundations — the trust-surface read-through

Every paper node beside the Lean statement that carries it, for all three formalized papers. The kernel has already checked every proof body; what it cannot check is whether each statement says what the paper says. That judgment requires a human reader — this page is the map for making it.

What a read-through certifies

A kernel-clean proof certifies that the body matches the statement, and nothing more. The statement — its definitions, hypotheses, and conclusion — is the trust surface. Reading a node means holding the two panes side by side and asking four questions:

1 · Fidelity. Does the Lean statement say what the paper node says — same quantifiers, same conclusion shape, no strengthened premise doing hidden work?
2 · Satisfiability. Is every hypothesis inhabitable? Constructed witnesses are named in the audit notes; a premise with no possible inhabitant makes the theorem vacuously true, and this failure mode has occurred (and been repaired) before.
3 · No smuggling. Is the conclusion (or the forcing step) taken as a hypothesis anywhere? Structures' fields are hypotheses too — see the field-freeze appendices.
4 · Metering. Where a paper's own statement quantifies over an efficiency class, check which class the Lean statement actually uses; the classes are not interchangeable, and the narrower ones appear only where a node is marked qualified.

What is on each card, and what is not

Every card is the same mechanical pair: the paper's printed statement, machine-converted from the committed TeX, beside the exact source text of the Lean statement (or statements) annotated with that node. Beyond that pair, the three papers carry different editorial material, because different material exists — and the difference is real, not a presentational choice:

Only Logical Induction has a strength classification and per-node reading notes. They are the product of a dedicated re-derivation pass and a machine-checked table; the other two libraries have had no such pass. No tier, audit note or reading note is shown for a paper that does not have one — the correspondence is what those sections claim, and it is all they claim.

How to use this page

Within each paper, nodes appear in that paper's own order, grouped by its own sections; definitions come first and are load-bearing for everything after. Where a node has several inventory endpoints, the ‹ › arrows page through all of them. Check-boxes track progress across all three papers and persist locally in the browser. Signatures are statements only, verbatim from source; file paths locate the full declaration. Paper statements are machine-converted from the arXiv TeX (custom macros expanded, rendered as MathML) — for any formula that looks off, the arXiv PDF is the authority; the Lean pane is exact source text.

Generated from the repository by scripts/gen-trust-surface.py, driven by the paper registry scripts/papers.py; node locations come from scripts/paper_nodes.py, the same module the per-paper provenance checkers use. The page carries a hash over every input — each paper's source, every library's Lean sources, the registry and the prose files quoted here — and scripts/check_trust_surface.py fails CI if it is stale.

Logical Induction

The two standing disclosures (apply to every node)

Sentences are propositional (Formula ℕ); the paper's first-order Θ enters through explicit interfaces. Efficient computability is the fuel-clocked interpreter model dd:fuel, not a machine complexity class. "Paper strength" always means within this disclosed model. Details: LogicalInduction/README.md, "The two modeling boundaries".

Tiers

paper strength · universal%%NUNI%% — the paper's own statement, for every logical inductor
paper strength · instantiated%%NINS%% — additionally holds of the constructed LIA with obligations discharged
qualified%%NQ%% — a named interface or class restriction is retained; the note says which

The tier and note on every card are read from scripts/coverage-classification.md, which is machine-checked against the endpoint inventory on every build, so a node cannot ship without a strength call. The qualified rows deserve the slow pass: each one's note names exactly what is retained and why.

Metering vocabulary

RpnSentenceCodes / symbol-metered classes are the faithful rendering of the paper's def:ec; whole-value classes (PolyNatCodes &c.) are provably narrower and appear only where a row is marked qualified.

Cartesian Frames

Garrabrant, Herrmann, Lopez-Wild (2021) · arXiv:2109.10996v1 · CartesianFrames/ · %%NCF%% nodes

No strength classification exists for this paper. There is no per-node tier and no per-node audit note below, because neither has been produced: the dedicated re-derivation pass and the machine-checked strength table that Logical Induction has were never run here. What the cards below assert is the correspondence — this printed node, these Lean statements — and nothing about how strong each rendering is. Read the statements.

Scope

All 60 numbered nodes of the paper carry Lean statements, across the main text and both appendices, with no modeling substitutions. Numbered nodes with no Lean statement: %%CF_MISSING%%. One node is formalized only in part, by user ruling — its card says so, in the ruling's own words.

How nodes are cited

Most nodes of this paper carry no LaTeX \label, so the printed Definition n / Claim n / Theorem n is the provenance key. scripts/check-cartesian-frames-nodes.py validates every annotation against the committed TeX fail-closed, and requires each annotated declaration to be listed in AxiomAudit.lean's CF-INVENTORY block. The cards below are built from those same annotations, so a node's Lean pane shows exactly the declarations that claim it.

Where the printed proof is the thing that is wrong

Defects found in this paper during formalization are recorded in CartesianFrames/notes/paper-errata.md; a node with an erratum carries it on its card. Consult it before concluding that a Lean proof diverges from the printed one — in several places the statement is sound and the printed proof is not.

Robust Cooperation in the Prisoner's Dilemma

Barász, Christiano, Fallenstein, Herreshoff, LaVictoire, Yudkowsky (2014) · arXiv:1401.5577 · ModalAgents/ · %%NMA%% nodes

No strength classification exists for this paper. As with Cartesian Frames, the cards below carry no tier and no per-node audit note, because none has been produced. They assert the correspondence only.

Scope — and what is deliberately absent

This formalization is scoped to modal agents rather than arbitrary arithmetic agents, so not every numbered node of the paper is claimed here. The nodes with no Lean statement annotated to them, computed from the source and the annotations: %%MA_MISSING%%. Two of those absences are documented decisions — Corollary 4.9 on CliqueBot is out of scope by design, as is Theorem 3.2's unexploitability conjunct, which quantifies over all opponents (see ModalAgents/README.md); the rest are simply unclaimed, and this page asserts nothing further about them. The provenance checker deliberately does not check the converse direction for this reason.

How nodes are cited

The paper labels only 22 of its nodes and leaves several formalized ones unlabeled, so the provenance key is the printed number, recomputed from the committed TeX by emulating the paper's shared section-scoped theorem counter (scripts/check-modal-agents-nodes.py). Note that the paper's definition environment is an uncounted trivlist: this paper numbers no definitions at all, so no definition can be cited and none appears below. The definitional content — modal agents, the four concrete agents — lives in Lean declarations attached to the theorems that use them.

Inventoried endpoints that deliberately carry no annotation

These endpoints are axiom-checked in AxiomAudit.lean's MA-INVENTORY block but claim no numbered node, because the fact each proves is unnumbered paper prose or a step inside a proof. The list is computed from the inventory; each reason is quoted from ModalAgents/README.md.

Temporal Inference with Finite Factored Sets

Garrabrant (2021) · arXiv:2109.11513 · FiniteFactoredSets/ · %%NFFS%% nodes

This formalization is in progress, and no strength classification exists for this paper. The cards below cover §2.1–§2.3 only — partitions, factorizations, and chimera functions. They carry no tier and no per-node audit note, because none has been produced; they assert the correspondence only. Nodes with no Lean statement annotated to them: %%FFS_MISSING%%.

How nodes are cited

The paper labels only 32 of its 98 numbered nodes, and the labels it does carry are working names (templabel1, templabel2), so the provenance key is the printed number, recomputed from the committed TeX (scripts/check-finite-factored-sets-nodes.py). Unlike the other counter-derived paper here, this one declares each environment without a [section] argument and without sharing counters, so every environment numbers independently and never resets: Definition 1…Definition 50 run the length of the paper alongside Proposition 1…Proposition 36. Note also that the source declares a lemma environment it never uses and a second lemma2 that also prints "Lemma" and carries all three printed Lemmas; the checker fails closed on that ambiguity rather than guessing.

Nodes rendered by Mathlib vocabulary rather than by a declaration

Several §2.1 nodes have no Lean carrier of this project's, because the modeling decisions in FiniteFactoredSets.lean render them with vocabulary Mathlib already has: Definition 2 (partition) is Setoid, Definition 5 (∼_X) is the setoid relation, Definition 6 (finer) is ≤, Definition 7 (Dis_S/Ind_S) is ⊥/⊤, and Definition 9 (∏(B)) is the dependent product. They are recorded in FiniteFactoredSets/README.md rather than inventoried, because there is no declaration of this project's to axiom-check.

One node carried only in part

bot_le_and_le_top carries the Proposition 2 annotation but states only that proposition's second sentence — the Dis_S / Ind_S bounds. Its first sentence, that the order is a partial order on Part(S), is Mathlib's PartialOrder (Setoid S) instance and has no declaration of this project's. So the card below pairs the whole printed proposition with a Lean statement covering half of it, on purpose; the other half is recorded in FiniteFactoredSets/README.md's table of Mathlib-rendered nodes.

One inverted convention, stated once

The paper's order glyphs run opposite to Mathlib's: it writes X ≥_S Y for "X is finer than Y", so the paper's ≥_S is Mathlib's ≤ on Setoid, and Definition 8's common refinement ⋁_S(C) — a join in the paper's notation — is Mathlib's sInf. The Lean statements use Mathlib's convention throughout and never introduce the paper's glyphs, so no statement has to be read under two conventions at once. When comparing a card's paper statement against its Lean statement, this is the one place the two will look like they disagree when they do not.
